# Performance Baseline

This file records the first benchmark baseline for the performance refactor.

## Command

```powershell
cargo run -p rust-core --release --bin perf_bench -- --full
```

## Environment

- Workspace: `C:\Users\krakotay\Documents\rust\excelsior`
- Date: `2026-04-06`
- Build profile: `release`
- Benchmark mode: `full`

## Scenario Config

- rows: `2000`
- cols: `20`
- style_rows: `1000`
- style_cols: `20`
- switches: `100`

## Results

| scenario | open_ms | mutate_ms | save_ms | total_ms | output_bytes |
| --- | ---: | ---: | ---: | ---: | ---: |
| append_tail | 0.295 | 24.216 | 5.518 | 30.029 | 323328 |
| append_overlap | 0.247 | 24.432 | 6.128 | 30.807 | 322676 |
| style_rect | 0.265 | 196.043 | 2.435 | 198.743 | 76196 |
| switch_and_save | 0.263 | 1.601 | 1.386 | 3.250 | 15160 |

## Notes

- `style_rect` is the clear hot scenario in the first baseline.
- Current benchmark output still includes debug `println!` lines from
  `XlsxEditor::open`; that should be removed during cleanup.
- `append_overlap` and `append_tail` are close on this workload size. Larger or
  more adversarial overlap cases should be added later to better expose the
  `set_cell` path cost.
- This baseline is enough to start Phase 2 and Phase 3 refactors with a fixed
  comparison point.

## Post-Change Spot Check

After the first Phase 3 change, `read_style_parts` now uses the parsed
`StyleIndex.xfs` cache instead of reparsing `styles.xml` for every merge.

Command:

```powershell
cargo run -p rust-core --release --bin perf_bench -- --full
```

Results:

| scenario | open_ms | mutate_ms | save_ms | total_ms | output_bytes |
| --- | ---: | ---: | ---: | ---: | ---: |
| append_tail | 0.321 | 23.856 | 5.795 | 29.972 | 323328 |
| append_overlap | 0.263 | 24.246 | 5.649 | 30.158 | 322676 |
| style_rect | 0.270 | 190.353 | 3.339 | 193.961 | 76196 |
| switch_and_save | 0.227 | 1.542 | 1.712 | 3.480 | 15160 |

Observed effect:

- `style_rect` improved from `198.743 ms` to `193.961 ms` total on this local
  run.
- This is a small but real win from a low-risk cache change.
- Bigger gains still depend on deeper style-cache and worksheet bulk-write
  refactors.

## Stress Benchmark Upgrade

The benchmark binary was later upgraded from a small synthetic check to a real
stress tool:

- streaming row generation instead of prebuilding the whole table in memory
- presets for `quick`, `full`, `million`, and `hardcore`
- persistent `.xlsx` inputs and outputs saved under `test/perf_outputs`
- autogenerated markdown report per run
- a `style_storm` scenario that applies many overlapping style waves

One verified run:

- output directory:
  `C:\Users\krakotay\Documents\rust\excelsior\test\perf_outputs\quick-1775439007`

Results:

| scenario | open_ms | mutate_ms | save_ms | total_ms | output_bytes |
| --- | ---: | ---: | ---: | ---: | ---: |
| append_tail | 0.258 | 59.169 | 12.214 | 71.641 | 899002 |
| append_overlap | 13.065 | 5723.637 | 9.291 | 5745.993 | 717509 |
| style_storm | 26.791 | 43416.742 | 20.380 | 43463.913 | 2002872 |
| switch_storm | 0.255 | 1.216 | 1.412 | 2.883 | 14375 |

What beast say:

- `style_storm` is now brutally expensive, which makes it a useful target for
  the next style refactors.
- `append_overlap` is also very expensive now, which exposes the current
  repeated cell-update path much more clearly than the old micro-benchmark.
